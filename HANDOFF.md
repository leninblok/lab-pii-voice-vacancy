- Подготовлены продуктовая идея, спецификация, план и инструкции агенту.

- Локальный Git связан с публичным [репозиторием GitHub](https://github.com/leninblok/lab-pii-voice-vacancy); ветка `main` отслеживает `origin/main`. `.env.local`, `sources/`, зависимости и сборка исключены из Git.
- После обновления Next.js до 16.4.6 аудит production-зависимостей не показал известных уязвимостей. Тесты прогресса, проверка типов и изолированная production-сборка прошли.
- Отдельные реальные вызовы к OpenAI подтвердили анализ, генерацию и распознавание короткого синтезированного русского аудио. Фактические результаты — в `docs/QA.md`.
- Есть инструкция пользователя, текстовая презентация и рабочий пакет сдачи в `delivery/`.
- По просьбе пользователя установлены навыки UI UX Pro Max и infostyle, интерфейс переведён на токены IDS и Inter. Источники и лицензии — в `design-system/MASTER.md` и `third-party-licenses/`.

4. Нужны публикация на Vercel, серверная переменная OpenAI в настройках Vercel и проверка опубликованной ссылки. Ключ в чат или Git не передавать.

## Локальные серверы в текущей сессии

- `http://localhost:3100` — первая production-сборка, оставлена запущенной для проверки пользователем.
- `http://localhost:3101` использовался для обновлённой production-сборки в изолированной временной папке. В ней проверены исправление оценки и повторные реальные вызовы; сервер остановлен после проверки.
- `http://localhost:3102` — первоначальная сборка редизайна IDS.
- `http://localhost:3103` — финальная локальная сборка IDS с правкой контраста, проверена HTTP-запросом и предложена пользователю для просмотра.

После проверки пользователем пересобрать приложение в папке проекта и запустить актуальную версию, если требуется локальный просмотр. Перед завершением работы остановить принадлежащие сессии серверы, когда пользователь закончит проверку.

## Публикация

1. Проверить вход в Vercel командой `npx --yes vercel whoami`.
2. Подключить проект к Vercel, безопасно добавить серверную переменную `OPENAI_API_KEY`, развернуть и пройти сценарий по HTTPS.
3. Добавить фактический URL и результаты проверки в `delivery/SUBMISSION.md`, `README.md` и `docs/QA.md`; отправить финальные изменения в репозиторий.
4. Указать пользователю реальные результаты и любые оставшиеся ограничения.

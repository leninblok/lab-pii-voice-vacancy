# Продуктовые решения и ограничения редизайна

Источник решений — три согласованных документа в корне проекта. Это описание целевого продукта; фактическую готовность отдельных функций проверяйте по журналу QA. Ранние решения сохранены в [истории проекта](PROJECT_HISTORY.md); при противоречии действуют последующие прямые решения пользователя.

| Решение | Зафиксировано |
| --- | --- |
| Основной объект | Живая редактируемая вакансия для будущего сотрудника; интервью помогает создать её и не превращается в чат. |
| Начало | На пустом экране — вопрос о вакансии и единый ввод. Документ создаётся только после первого успешно обработанного содержательного ответа. |
| Темы | Задачи, проект в ближайшие шесть месяцев, продолжение после них и навыки; это направления интервью, а не обязательные разделы документа. |
| Диалог | Любой ответ может содержать сведения для нескольких тем; по непокрытому аспекту задаётся короткий вопрос, пропуск не создаёт фиктивный прогресс. Внеочередные сведения попадают в вакансию без новой обязательной темы. |
| Индикаторы | Четыре линейных индикатора тем, без глобального процента и кольца; пороги 0, 1–39, 40–74, 75–100 — рабочая рубрика, а не научная метрика. Существенный пробел не позволяет считать тему раскрытой. |
| Документ | Структурированные блоки со стабильными ID; нет обязательных пустых разделов. Изменения одного ответа применяются целиком, устаревшие результаты не перезаписывают новую версию. |
| Редактура | Сохранять смысл, конкретику и авторский тон; не придумывать факты. Новое явное решение имеет приоритет; не просить согласование каждой редакторской правки. Правила типографики не должны портить технические названия. |
| Ручные правки | Редактирование напрямую и автосохранение; отложенный анализ обновляет оценки и вопрос, но не переписывает набранное. Метаданные ручных правок хранятся отдельно от истории операций. |
| Голос | Реакция на реальный уровень сигнала и таймер; отмена сохраняет набранный текст; после остановки текст и аудио обрабатываются как один ответ. Постоянная история аудио и расшифровок не создаётся. |
| Ошибки | Данные неуспешной попытки временно доступны для повтора в текущей сессии; новая попытка не должна приводить к дублированию или применению устаревшего результата. После закрытия вкладки восстановление записи не обещается. |
| История | Вакансии и документ сохраняются локально; история вакансий и история изменений не являются историей переписки. До 50 состояний и семи дней для истории изменений; актуальный документ не удаляется. |
| Возврат | Учитывать последнюю правку, успешный экспорт и интервал 60 минут по SPEC; автоматически переключать уже открытую вкладку нельзя. Выбор пользователя имеет приоритет. |
| Экспорт | Копировать описание без названия с форматированием и запасным текстовым вариантом; PDF включает название и описание, без новой генерации. Время экспорта фиксировать только после успеха действия в смысле SPEC. |
| Дизайн | Белый фон, спокойная монохромная типографика и компактный интерфейс. IDS и навыки анимации — инструменты, не основание добавлять элементы сверх спецификации. Доступность и reduced motion обязательны. |
| Границы | Нет статусов вакансии, пустых шаблонных секций, чата, поиска, удаления или дублирования вакансий, отдельных файлов TXT/Markdown/HTML и вариантов «под площадку». |

## Практические уточнения для реализации

- У документа с одним названием нет описания для копирования. Не подменять описание заголовком, не считать пустое копирование успешным; PDF с названием должен оставаться возможным. Конкретный текст объяснения подобрать при реализации согласно редакторским правилам.
- При проверке PDF подтвердить совместимость выбранного механизма с окружением, кириллицей и разрывами страниц, прежде чем принимать зависимость. Генерация и начало скачивания не доказывают, что файл физически сохранён пользователем.
- API-схема и автоматические проверки уменьшают риск выдуманных фактов, но не доказывают семантическую достоверность каждого ответа. Нужны тестовые кейсы и ручная оценка.
- Примеры вакансий получены; все три изучены; сохранённую страницу третьего примера предоставил пользователь. Примеры задают редакционную планку и не служат источником фактов.

## Последующее решение пользователя — индикатор и пропуск

Пользователь попросил убрать круг у активной темы и кнопку «Пропустить». Это решение имеет приоритет над ранней спецификацией: остаются горизонтальные индикаторы тем и свободный выбор темы. В исходном тестовом задании круговая анимация упоминалась отдельно, поэтому это осознанное отклонение от первоначального критерия, которое нужно обозначить при сдаче.

## Последующее решение пользователя — ввод и эталонный документ

- Панель интервью расширена примерно на 10%: максимальная ширина — 836 px. Ширина основного документа не меняется, поэтому строка ввода остаётся визуально ведущей, но текст не становится слишком широким для чтения.
- Во время записи поле не получает и не сохраняет фокус: в нём остаются только крестик для сброса, волна фактического сигнала и стрелка для остановки и отправки записи. Визуальный таймер убран; технический лимит записи в две минуты сохранён.
- Во время обработки исходный текст и действия не показываются под статусом. Строка становится неактивной и последовательно сообщает «Расшифровываем запись…» и «Собираем вакансию…» с одним индикатором.
- В локальной истории создаётся один явный «Пример для редактирования» — полностью заполненная вакансия продуктового дизайнера. Это демонстрационный документ для стенда, а не шаблон, не источник фактов для генерации и не замена текущей вакансии пользователя. Его можно открыть и править как обычный локальный документ.

## Последующее решение пользователя — спокойная панель интервью

Пользователь отказался от полноцветной оранжевой панели как от слишком громкой. По указанному узлу Figma активная панель теперь почти белая (`rgba(255,255,255,.98)`) с тонкой нейтральной границей и существующей мягкой тенью. Цвет `#ff4800` остаётся только у заполненной части линейного индикатора темы и у завершающего действия PDF. Ширина 836 px, заданная предыдущим решением пользователя, сохраняется: новый Figma-узел использован исключительно как цветовая референция.

## Последующее решение пользователя — статусы действий и hover

- Успешные «Скопировать» и «Скачать PDF» больше не создают текст под панелью ответа. Иконка в соответствующей верхней кнопке становится галочкой на 1,8 секунды; скрытое live-сообщение сохраняет обратную связь для скринридера.
- Текст рядом с полем остаётся только для ошибок, повтора записи и состояний, где пользователь должен понять проблему или сделать следующий шаг.
- Нейтральные действия в верхней панели, боковой панели и поле получают одинаковый hover: фон `#ebedef`, основной цвет текста; при нажатии — короткое уменьшение до 97%. У акцентного PDF hover — предсказуемое тёмное состояние того же оттенка. Ссылочное действие «Продолжить» меняет только цвет.

## Последующее решение пользователя — старт и первый переход

- Галочка успеха не меняет цвет кнопки: это только краткая замена иконки. Не использовать зелёный или другой дополнительный семантический цвет для обычного успешного экспорта.
- Стартовый экран объясняет сценарий одной короткой фразой: пользователь рассказывает о будущем сотруднике голосом или текстом, получает черновик и затем только полезные уточнения. Поле лежит прямо на фоне; у него нет внешней пустой карточки.
- Когда на пустом старте появился текст, под полем мягко раскрывается небольшая плашка о следующем шаге. После первого успешного ответа документ появляется сверху, а нижняя панель закрепляется в своей конечной позиции. Это редкий переход первого сценария, поэтому допустимы короткие `transform`/`opacity`-анимации; последующие правки не перемещают документ.
- Новый заголовок вакансии сохраняет настоящую редактируемую поверхность. Краткий эффект появления текста и каретки служит обратной связью, но не задерживает выделение и ручную правку, не имитирует набор ложными символами и отключается вместе с остальным движением при `prefers-reduced-motion`.

## Последующее решение пользователя — точный первый переход

- Стартовое поле выравнивается с колонкой текста: рабочая ширина 720 px, а не максимальная ширина нижней панели интервью.
- Во время обработки используется одна неизменная, тихая фраза «Готовим вакансию…» и уменьшенный полупрозрачный индикатор с медленным оборотом. Не показывать технические шаги и не менять текст статуса в процессе.
- Первый переход должен быть двухфазным: после ответа начальная сцена 320 мс уходит из текущего положения, затем появляется документ. Нельзя сначала заменить DOM, а затем пытаться анимировать появившееся состояние.
- Изменённые фрагменты открываются слева направо короткими шагами. Заголовок получает измеренную ширину и каретку, которая проходит по этой ширине. Это визуальное раскрытие настоящего текста, а не подмена его отдельной строкой; для обычных обновлений эффект короткий и отменяется системным reduced motion.

## Последующее решение пользователя — правдивый статус и каскад документа

- Формулировка «Готовим вакансию…» отменена: она не описывает происходящее во время голосового ввода. Для аудио показываем один неизменный спокойный статус «Расшифровываем запись…», для текстового ответа — «Обрабатываем ответ…». Статус и медленный лоадер имеют пониженную контрастность; поле в это время недоступно и визуально почти сливается с фоном.
- После ответа новые и изменённые блоки документа раскрываются в порядке чтения — сверху вниз, с короткой последовательной задержкой. Нельзя показывать все новые абзацы одновременно. Эффект применяется к существующим редактируемым DOM-узлам и не должен мешать выделению или вводу.
- Ошибка отправки занимает место самого поля, сохраняя его размеры и скругление. Слева — сброс неотправленного ответа, в центре — понятное сообщение, справа — повторная отправка. Не выводить дополнительную плашку ошибки ниже панели и не возвращать микрофон, пока существует неотправленный ответ.
- Если результат сервера нельзя применить из-за новой версии документа или он не меняет документ, это также считается неотправленным ответом. Нельзя молча очищать состояние обработки и оставлять старый текст без объяснения.

## Последующее решение пользователя — спокойные состояния поля и видимый прогресс

- Фокус поля и hover нейтральных иконок используют один оранжевый `#ff4800`. Для hover не добавлять серую или цветную заливку: меняется только цвет иконки; нажатие может кратко уменьшать кнопку.
- Подсказка «Соберём первый черновик и подскажем, что ещё уточнить» удалена как дублирующая смысл стартового текста.
- Во время обработки поле сохраняет те же размер и внутреннюю сетку: оно белое, без рамки, сообщение находится у левого края на месте текста, тихий лоадер — справа. Не центрировать статус и не добавлять второй блок под полем.
- Состояние неотправленного ответа использует ту же белую поверхность без рамки. Внутри остаются краткое объяснение, сброс слева и повтор справа.
- В строке тем всегда видны все четыре направления. Достаточно раскрытая тема не кликабельна и не получает hover, но сохраняет видимость: линия плавно заполняется до конца, справа от названия появляется оранжевая галочка.

## Последующее решение пользователя — акцент действия и волна обработки

- Основное действие отправки — оранжевая кнопка. При hover она становится краснее; это исключение из правила нейтральных иконок без заливки. Аналогично ведёт себя акцентный экспорт PDF после завершения интервью.
- Крутилка обработки заменена декоративной бледной волной, занимающей спокойную серую поверхность поля. Волна не имитирует уровень микрофона и не сообщает ложных данных о записи: это только непрерывная обратная связь об ожидании. Статус остаётся в той же строке.
- Заполненная тема использует оранжевый текст, оранжевую галочку и полностью заполненную линию. Незавершённые темы становятся заметнее предыдущего слишком бледного состояния, но не конкурируют с активной.

## Последующее решение пользователя — непрерывная волна записи

- После отправки голосового ответа не заменять поле новой сценой с подписью. Волна сохраняет то же место и ширину, а реальные полосы записи плавно переходят в бледную декоративную волну ожидания.
- Кнопки сброса и отправки остаются в DOM на короткий переход, но уходят через opacity и scale, сохраняя геометрию поля. Не сдвигать волну и не менять высоту строки.
- Визуальной подписи во время ожидания нет. Доступное название «Расшифровываем запись…» или «Обрабатываем ответ…» остаётся только для скринридера.

## Последующее решение пользователя — список вакансий и первый текст

- Текущая вакансия в боковой панели выделяется лёгкой оранжевой поверхностью; её название оранжевое, дата — более бледная оранжевая, и оба не меняются по hover. Остальные вакансии чёрные; только их hover переводит название в оранжевый, а дату — в более бледный оранжевый.
- Первый ответ — редкий переход с целью объяснить смену сцены, но не отвлекать от работы. Стартовые текст и поле коротко передают сцену (текст — на 28 px вверх, поле — на 22 px вниз), с opacity и blur; новый документ и закреплённая панель входят следом. Не гонять элементы через весь экран: это чтение и рабочий ввод, а не декоративная заставка.

## Последующее решение пользователя — асимметричная обратная связь

- Функциональные hover и focus появляются мгновенно, чтобы интерфейс сразу отзывался на действие. Их снятие длится 300–360 мс и использует `ease`, чтобы цвет, рамка и кольцо фокуса спокойно возвращались в обычное состояние.
- В истории вакансий показывать время последней правки. Формат: «Сегодня, 14:23», «Вчера, 09:10», далее в текущем году — «10 ноября, 14:23», в другом — «10 ноября 2025, 14:23»; не добавлять «г.».
- Правило применяется только на указателях с настоящим hover; на touch-устройствах ложные hover-состояния не создаются.

## Обратная связь в интервью

- Под вопросом есть один спокойный поясняющий слой: он коротко объясняет, какие сведения помогут, и даёт один пример. Подсказки привязаны к теме интервью — задачам, первым шести месяцам, дальнейшей работе или навыкам — и не выдаются за факты конкретной вакансии.
- После успешного ответа панель сообщает, какую часть вакансии учла. Подтверждение строится только из факта успешного обновления и активной темы, а не из свободного пересказа модели.
- В финале вместо неопределённого «Что-нибудь ещё?» панель говорит «Вакансия готова», объясняет, что можно добровольно уточнить, и предлагает поле «Добавьте важную деталь…». Не добавлять чипы, вторую карточку или чат.

## Уточнение сетки боковой панели

- Подсказка под вопросом лежит ближе к вопросу: это одна смысловая группа, а не самостоятельный абзац.
- Заголовок «Вакансии» выровнен с текстом списка. «Новая вакансия» использует кегль списка, среднее начертание и плюс того же визуального веса.
- Кнопка открытия и закрытия панели — один постоянный элемент. Он плавно переезжает к правому краю открытой панели, а две пиктограммы аккуратно сменяют друг друга через opacity и transform; не подменять кнопку отдельным элементом в шапке панели.

## Стартовый экран в языке пользователя

- Не использовать служебный ярлык «Вакансия голосом». Заголовок обращается к задаче пользователя: «Расскажите, кого вы ищете?».
- Пояснение называет весь путь: рассказать о роли, получить черновик, ответить только на нужные вопросы, отредактировать текст и скачать PDF. Не описывать внутреннюю технологию.
- Заголовок и пояснение образуют компактную смысловую группу; поле находится ниже, через более заметную паузу. У статичных поясняющих фраз нет завершающих точек; это не относится к тексту вакансии, вопросам и сообщениям об ошибке.
- В заголовке фиксированный перенос после «Расскажите,». Пояснение не повторяет вопрос: оно говорит о будущей работе, черновике, нужных уточнениях, ручной правке и PDF.
- Ключевое обещание стартового текста: пользователь может рассказать о работе «как получится», а сервис проведёт по шагам, подскажет недостающие детали и соберёт понятную вакансию. Формулировка не обещает автоматическую публикацию или качество без участия пользователя.
- Межстрочный интервал двухстрочного заголовка — 1.01, чтобы строки были одной компактной группой без наложения.

## Локальная анимация правок

- Стартовое поле равно ширине поясняющего текстового столбца — 610 px на широком экране, без отдельной более широкой сетки.
- Не показывать служебные подписи вида «Учли…». Под вопросом остаётся одна серая тематическая подсказка; она не конкурирует с вопросом и не дублирует результат правки.
- При обновлении существующего фрагмента текста неподвижны общий префикс и окончание. Только заменяемые символы поочерёдно зачеркиваются и удаляются, затем новый фрагмент печатается. Новый текст остаётся красным дольше, проходит через оранжевый и возвращается к основному цвету за 4,8 секунды.
- Во время короткого проигрывания правки редактор временно readonly: это не даёт пользователю случайно ввести текст в промежуточную версию. При `prefers-reduced-motion` показывается сразу итоговый текст без по-символьного перехода.
